# Style Guide

## Правило №0: Alpha Freeze

До Alpha 0.1 не добавляются новые крупные модули, плагины или подсистемы.
Все идеи фиксируются в `docs/IDEAS.md` и `docs/labs/` и рассматриваются только после первого рабочего релиза.

## Правило №1: Operator First

Любая новая функция должна отвечать на вопрос:

> "Помогает ли она оператору быстрее и надежнее обработать фотографии?"

Если ответ "нет" — функция не попадает в Desktop. Она относится в Studio или Labs.

## Структура кода

- Каждый модуль имеет одну ответственность
- Имена файлов и классов говорят сами за себя
- Без лишних абстракций
- Без преждевременной оптимизации

## GUI

- Сначала функциональность, потом дизайн
- Минимум элементов на экране
- Focus Mode для длительной работы
- Без перегруженных настроек в интерфейсе

## Производительность

- Все длинные операции — через JobManager
- Прогресс и отмена обязательны
- Без блокировки UI
- Память: не держим всё в RAM

## Безопасность

- Все действия пишутся в History
- Backup автоматический
- Откат без потерь данных

## Именование

- `recognition/` — движки
- `search/` — индексы
- `storage/` — данные
- `desktop/` — интерфейс оператора
- `core/` — фундамент
- `plugins/`, `studio/`, `labs/` — будущее

## Запрещено

- Зашивать пути в код
- Зашивать пороги в код
- Классы длиннее 300 строк
- Функции длиннее 50 строк
- Смешивать GUI и бизнес-логику
- Создавать менеджеров без EventBus

## Тестирование

- Каждый сервис тестируется изолированно
- Desktop тестируется через моки
- Без тестов — без коммита

## Документация

- Каждый модуль — одна строка docstring
- Complex logic — комментарий
- ARCHITECTURE.md актуальна всегда
- ROADMAP.md обновляется после каждого спринта

## Коммиты

- Один коммит = один логический модуль
- Сообщение коммита = что сделано
- Без "fix typo" коммитов
- Без коммитов "just in case"

## Git workflow

- main — стабильная версия
- Не коммитим secrets
- Не коммитим workspace
- .gitignore всегда актуален
